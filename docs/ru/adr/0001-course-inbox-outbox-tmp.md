# ADR-0001: Конвейер курсов `inbox → tmp → outbox`

English: [../../en/adr/0001-course-inbox-outbox-tmp.md](../../en/adr/0001-course-inbox-outbox-tmp.md).

- **Статус:** Принято
- **Дата:** 2026-07-24
- **Контекст:** большой архив видеокурсов, ограниченное место на диске, реальные курсы тестируются внутри репозитория

## Контекст

Нужный поток:

1. Положить папку курса (все файлы) в **inbox**.
2. Инструмент сжимает видео через NVENC.
3. Если **общий размер курса уменьшился** — перенести сжатое дерево в **outbox** **вместе со всеми невидеофайлами**.
4. Если **не меньше** — перенести **оригинальный** курс в **outbox** как есть.
5. После обработки inbox для этого курса опустошается.

Диск ограничен: **не** дублировать весь курс в tmp на всё время прогона.

**Имена папок только на английском** (ASCII) — для инструментов, git и терминалов в Windows.

## Решение

### Пути: значения по умолчанию внутри проекта, всё переопределяется

**Корень по умолчанию:** `<repo_root>/courses/`  
(корень репозитория = каталог с `pyproject.toml` / этот git-репозиторий — не обязательно cwd процесса).

| Роль | По умолчанию | Переопределение |
|------|--------------|-----------------|
| Inbox | `<project>/courses/inbox` | CLI `--inbox` / env `SMART_CONVERT_INBOX` |
| Outbox | `<project>/courses/outbox` | CLI `--outbox` / env `SMART_CONVERT_OUTBOX` |
| Work (`tmp`) | `<project>/courses/tmp` | CLI `--tmp` / env `SMART_CONVERT_TMP` |
| Корень трёх каталогов | `<project>/courses` | CLI `--courses-root` (тогда `inbox`/`outbox`/`tmp` — дочерние, если не заданы явно) |

Приоритет: **флаг CLI > env > значение по умолчанию в проекте**.

Почему значения по умолчанию в репозитории: удобные ручные тесты рядом с кодом.  
Почему переопределение: боевой архив может быть на другом диске; держите три каталога на **одном томе**, чтобы `move` не превращался в copy+delete.

### Раскладка по умолчанию

```text
<project>/courses/
  inbox/    # исходные курсы
  outbox/   # результат (сжатый или оригинал)
  tmp/      # только работа кодирования; не долговременное хранилище
```

| Путь (по умолчанию) | Роль |
|---------------------|------|
| `…/inbox/<course_name>/` | Единица работы = **одна папка первого уровня** |
| `…/outbox/<course_name>/` | Финальное место после обработки |
| `…/tmp/<course_name>/` | Временные кодировки; очищается после успеха/пропуска |

Медиа **не** коммитятся (gitignore содержимого дерева по умолчанию); в git остаются только README-заглушки. Переопределённые пути вне репозитория — ответственность пользователя.

### Единица работы

- **Курс** = каталог `courses/inbox/<name>/` (рекурсивно: видео, PDF, код, субтитры, …).
- Отдельные файлы прямо в `inbox/` (не в папке курса) вне scope v1 (ошибка + подсказка).
- Идеальное короткое имя папки + опциональные метаданные/маркер корня `course.json`: [ADR-0002](./0002-course-folder-naming.md). Конвейер считает имя папки непрозрачной идентичностью и не переименовывает его.

### Когда курс «стал меньше»

Сравнивать **полный размер дерева** (все файлы), а не только видео:

`size(assembled) < size(original_course) * (1 - min_course_savings)`

Порог по умолчанию близок к экономии на файл (например 5–10%), через `--min-course-savings`.

На каждое видео по-прежнему действует MVP-логика (HEVC vs AV1 sample, пропуск файла, если невыгодно). Итог по курсу = выбранные видео + нетронутые невидеофайлы.

### Поток обработки (с учётом места на диске)

**Не** копировать весь курс в tmp.

1. `original_size = du(courses/inbox/Name)`.
2. Для каждого видео:
   - кодировать в `courses/tmp/Name/<relative_path_with_new_ext>`;
   - если сжатый файл **не** меньше (порог на файл) — оставить оригинал, удалить неудачный вывод в tmp;
   - если меньше — пометить сжатый как победитель.
3. **Не** предкопировать невидео в tmp; учитывать их размер из `inbox/`.
4. `candidate_size` = сумма (выбранные видео) + размеры всех невидеофайлов.
5. **Если кандидат выгоден:**
   - собрать `courses/outbox/Name/`:
     - невидео: `move` из `inbox` (тот же том → rename);
     - выигравшие видео: `move` из `tmp`;
     - проигравшие видео: `move` оригиналов из `inbox`;
   - удалить опустошённые `inbox/Name` и `tmp/Name`.
6. **Если невыгодно:**
   - `move courses/inbox/Name → courses/outbox/Name`;
   - полностью удалить `tmp/Name`.
7. При ошибке посреди прогона: оставить курс в `inbox/` (или пометить `Name.failed`); опционально сохранить tmp для отладки; **никогда не публиковать частичное дерево в `outbox/`**.

### Конфликты имён

Если `courses/outbox/Name` уже существует — **ошибка** (без тихой перезаписи). Позже: `--overwrite-outbox` или суффикс с датой.

### Зачем нужен `tmp`

Без отдельного рабочего каталога нельзя:

- сохранить источник нетронутым до решения на уровне курса;
- сравнивать размеры, не портя inbox;
- отбросить плохое сжатие простым удалением tmp.

`tmp/` одноразовый; после успешного прогона курса он не должен его хранить.

### CLI (следующий шаг реализации)

```text
uv run smart-convert-course
uv run smart-convert-course "Name"

uv run smart-convert-course --courses-root "D:\Archive\courses"
uv run smart-convert-course --inbox "E:\inbox" --outbox "E:\outbox" --tmp "E:\work"
```

Одиночный файл `smart-convert path.mp4` остаётся для отладки кодека; UX архива — конвейер по папкам.

## Последствия

### Плюсы

- Понятные имена inbox/outbox для ручных тестов внутри проекта.
- Боевые пути могут быть на другом диске без изменений кода.
- Английские ASCII-имена папок избегают боли с консолью/git/путями в Windows.
- Невидеофайлы сохраняются при успехе.
- Невыгодные курсы переносятся как оригиналы; tmp отбрасывается.
- Нет обязательного полного дубликата курса.

### Минусы / риски

- Кодированию нужно свободное место ≈ размер сжимаемых видео, пока существует tmp.
- Cross-volume `move` становится copy+delete — держите inbox/outbox/tmp на одном томе.
- Смешанные курсы (часть видео сжалась, часть нет) требуют аккуратной сборки — поддержано по замыслу.
- Надёжно определять корень проекта при editable-установке из другого cwd.

## Отвергнутые альтернативы

| Альтернатива | Почему нет |
|--------------|------------|
| Кодирование на месте в `inbox/` | Нельзя чисто откатить; портит inbox |
| Всегда копировать в `outbox/`, потом кодировать | Удваивает использование диска |
| Только `tmp/` без `outbox/` | Нет стабильного outbox |
| Имена папок `before`/`after` | Пользователь предпочитает `inbox`/`outbox` |
| Кириллические имена папок по умолчанию | Требуются только английские пути |
| Пути только внутри проекта | Нельзя указать архив на другом диске |
| Только env, без CLI | Неудобно для разовых запусков |
| «Курс меньше» только по размеру видео | Игнорирует материалы; пользователь думает целыми курсами |
